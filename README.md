### ヒーローの写真（2026-08-12 追加）

トップのヒーローは球場の写真を **7秒ごとに** 切り替える（`HeroSlideshow`）。

| 場所 | 中身 |
|---|---|
| `assets/hero/` | 原本。リポジトリに入れる前の大きいまま |
| `public/hero/` | 配布用。**直接置き換えない**（`npm run hero` で作る） |
| `src/lib/hero.ts` | 表示する順番・クレジット・何が写っているかのメモ |

```
npm run hero
```

幅1920pxまで縮めて JPEG(q78) にする。スマホで撮った写真は2MBを超えることがあり、
リポジトリに履歴として残り続けるため、入れる前に一度だけ小さくする。

**写真の上には無彩色の黒の膜を重ねている**（`globals.css` の `.hero-veil`）。
写真ごとに明るさが違うので、素のまま文字を載せるとコントラストが写真次第になる。
かといって一様に濃くすると写真が見えない。**見出しのある側だけ濃くしている。**

**膜の色は 2026-08-13 に navy-900 から黒に変えた。** ネイビーだと写真全体が青くカブり、
夕暮れも土の色も同じ青に寄ってしまって「写真が見づらい」という指摘があったため。
黒は色を変えずに暗くするだけなので、同じコントラストをより薄い膜で達成できる。
**青に戻さないこと。**

| 幅 | 膜 | 理由 |
|---|---|---|
| 1024px以上 | 左62% → **460px**で58% → **660px**で25% → 右端8% | 見出しが左だけなので右は写真を見せる |
| 1024px未満 | 一様に58% | 見出しが幅いっぱいに広がるので右だけ薄くできない |

**区切りは割合ではなく px。**（2026-08-13 に % から変えた）ヒーローの文はどこで
折り返すかを `<br>` で決めてあるので、**いちばん長い行の幅はヒーローの幅が変わっても
一定**（実測446px。ヒーロー自体は613〜706pxの範囲で伸び縮みする）。割合で区切ると、
ヒーローが狭いときだけ文字が薄い側にはみ出す。実際 `60%` で区切っていたとき、
1024px幅（ヒーロー613px）では説明文が **72.7%** まで届いていて、その位置の膜は
0.37、コントラストは 3.17:1（基準4.5:1）だった。
**README に「幅の59%で終わる」と書いてあったのは広い画面だけを見た数字。**

濃さを決めているのは白文字ではなく**オレンジの見出し**（accent-500、相対輝度0.378）。
大きな太字なので基準は 3:1 だが、白の 4.5:1 よりこちらのほうが厳しい。
いちばん明るい青空の写真（相対輝度0.55）の上での実測値:

| | 末尾 | その位置の膜 | コントラスト |
|---|---|---|---|
| 見出し（オレンジ・基準3:1） | 392px | 0.586 | **3.23:1** |
| 説明文（navy-100・基準4.5:1） | 446px | 0.581 | **6.52:1** |

**文言や `<br>` の位置を変えたら 460px を測り直すこと。** 測り方は開発サーバーで
`Range#getClientRects()` の右端を読む（ブラウザペインのスクリーンショットは
撮れないことが多い。README「見た目の確認」を参照）。

被写体が左に寄っている写真は `flipHorizontal: true` で左右反転させ、
見出しと重ならないようにしている（`ball.jpg`）。
**文字が写っている写真には使わない**（鏡文字になる）。

**`prefers-reduced-motion: reduce` のときは切り替えない。** 自動で動き続ける背景は
設定で止められる必要がある（WCAG 2.2.2）。止めても1枚目が出るので情報は失われない。

写真は装飾なので `alt=""`。ただし**クレジットは読み上げ対象に残す**
（帰属表示は装飾ではなくライセンス上の義務）。

⚠️ **出典が確認できない写真を足さないこと。**
このサイトは広告を載せる＝営利なので、「個人利用のみ可」の素材は使えない。
`src/lib/hero.ts` の `source` に**必ず出典を書く**（画面には出さない記録用）。

### 学校データの作り方

**学校名・所在地・設置区分は文部科学省「学校コード一覧」から機械的に取る。**
生成AIに学校名を書かせない（存在しない学校が必ず混ざる）。

```
node scripts/build-school-seed.mjs
```

CSVは初回だけ自動でダウンロードして `data/` に置く（gitには入れない）。
高校・中等教育学校は東日本／西日本の2本、**高専は大学・短大と同じ別ファイル**にある。
出力は `supabase/schools_<地方>.sql`。**このSQLは生成物なので直接編集しない。**

**必ず全地方を一度に作る**（引数なしで実行する）。slugの重複は地方をまたいで
起きるため（本庄と本荘、足立と安達、大野と小野はローマ字にすると同じになる）、
地方ごとに走らせると重複に気づけず、INSERT時に後の学校が前の学校を上書きしてしまう。
重複したときは後から来たほうに地区名を足して分ける（`saitama-honjo` など）。
**先に処理した地方が短いslugを取るので、地方を足すときは `REGIONS` の末尾に足すこと。**
途中に入れると既存のURLが変わる。

公的データに無くて補っているのは3つだけ。

| ファイル | 補うもの | なぜ必要か |
|---|---|---|
| `data/school-kana.json` | 校名の読み | CSVにふりがなが無く、URLのローマ字slugが作れない |
| `data/name-override.json` | 表示名 | 分校や「川口市立高等学校」など、機械的に短縮できない校名 |
| `data/establishment-override.json` | 設置区分 | 校名に設置者が入っていない学校（ふたば未来学園など） |
| `data/district-override.json` | 地区 | 住所から決められない学校があれば学校コードで指定する |
| `data/hokkaido-shinkokyoku.json` | 振興局 | 北海道の南北を市町村から決めるための対応表 |
| `data/baseball-clubs.json` | 硬式野球部の有無 | 文科省データに部活動が無い。各県高野連の加盟校名簿から |

### 硬式野球部の絞り込み

掲載するのは硬式野球部がある学校だけにする。判断は**各都道府県高野連の加盟校名簿**に
よる。**推測で決めない**（校名や設置区分からは分からない）。

`data/baseball-clubs.json` に名簿を県ごとに入れる。名簿がある県は、載っていない学校を
`status = 'draft'` にする（RLSで公開側から見えなくなる）。**消さずに下書きにする**のは、
名簿が変わったときに戻せるようにするため。名簿を入れていない県は全校を公開したままに
する。全部を下書きにするとサイトから学校が消えてしまうので、調べた県から順に絞る。

名簿は「千葉」「市立千葉」「東金商」「木更津高専」のような短縮形で書かれている。
照合は 芯 →「市立」付き → 高専の言い換え → 省略形の補完（商→商業など、残りが
1文字のときだけ）の順で行い、**照合できなかったものは両方向とも報告する**。
実行結果の「名簿にあって照合できず」が0件になるまで確かめること。

名簿を入れていない県でも、**校名に「女子」が入る学校は下書きにする。**
高野連の硬式は男子のみで女子校は加盟できないため、校名から機械的に判断できる
数少ない確実な除外条件。ただし奈良女子大学附属中等教育学校のように
名前に女子が入っていても共学の学校があるので、`CO_ED_DESPITE_NAME` で除く。

読みは芯の部分（「千葉県立千葉高等学校」なら「千葉」）をキーにする。
同じ芯で読みが違う学校（麻生＝あそう／あさお、東＝あずま／ひがし）は
**学校コードをキーにして個別に指定する。**
値をローマ字で書くと変換せずそのままslugになる（広尾＝hiroo など、
長音ではない母音の並びで使う）。

**読みは目視で確認すること。** slugは公開後に変えられない。

地区の判定は住所から機械的に行っている。東京は多摩地域＋世田谷・練馬・杉並が
西東京、北海道は振興局（石狩・空知・後志・胆振・日高・渡島・檜山が南）。
区割りが変わったらスクリプト内の `resolveTokyoDistrict` と
`data/hokkaido-shinkokyoku.json` を直す。

#### 成績（`result`）の決め方

**「3勝」ではなく「ベスト16」のように到達段階で持つ。**
勝ち抜き戦なので、試合の勝敗グラフを決勝までさかのぼれば、
その試合が決勝の何回戦前か（k）が確定する。k=0の敗者が準優勝、k=1が4強、
k=2が8強……と2倍ずつ増える。**決勝から逆算するのでシードや不戦勝の影響を受けない。**

実装で踏んだ落とし穴が2つある。直すときは注意すること。

- **勝者の残り試合数を数えてはいけない。** 勝者は次に負ければそこで終わるので、
  それだと決勝以外のほぼ全試合が「決勝の1つ前」になり、ベスト4が1大会あたり
  4.6校という結果になる。**「勝者が次に出る試合」を辿って決勝まで遡る**のが正しい
- **無敗であることを優勝の根拠にしてはいけない。** 負け試合を取りこぼした学校も
  敗戦0になるため、偽の優勝校ができる。**優勝は決勝の勝者に限る**

到達段階が確定しない場合（試合を取りこぼしている、敗戦が2つある、開催中）は
**推測で埋めず `result` を null にする。** 現在110件（1.7%）。

分布は次のとおりで、大会数199に対して整合している。

| 優勝 | 準優勝 | ベスト4 | ベスト8 | ベスト16 | ベスト32 | 初戦敗退 | 不明 |
|---|---|---|---|---|---|---|---|
| 195 | 191 | 391 | 762 | 1,103 | 443 | 3,142 | 110 |

**照合キーは表示名ではなく記事名にしている。**「銚子商」ではなく
`[[千葉県立銚子商業高等学校|銚子商]]` のリンク先を使う。さらに好都合なことに、
統廃合・改称した学校はWikipedia側が既に現存校の記事を指している
（秋田市立→秋田県立秋田中央、一関商工→一関学院）。**「現存校に引き継ぐ」方針と
一致するので、旧校名の対応表はほぼ不要になった。**

**中止大会を取り込まない。** 1918年（夏第4回・米騒動）、1941年（夏第27回）、
2020年（春第92回・夏第102回）は出場校が決まっていても1試合も行われていない。
「試合が0件の大会は除外」で自動的に落ちる。この4件は史実と一致する。

**自己検証を2つ入れてある。Wikipediaが二次情報である弱点はここで潰す。**

| 検証 | 内容 |
|---|---|
| 1 | 記事の「2年連続8回目」と数えた出場回数が一致するか |
| 2 | 勝ち抜き戦なので優勝校以外の敗戦数は必ず1 |

検証1は**大会の二重計上を実際に見つけた。** 選抜は1948年の学制改革で回数が
第1回にリセットされ1955年に通算へ戻ったため、「第6回選抜」が「第25回選抜」へ
リダイレクトされ、同じ大会を2度取り込んでいた。解決後の記事名で重複を除いている。

検証2に引っかかる記録は `result` が null になる（推測で埋めない）。

**不一致はすべて「数えたほうが少ない」方向**（取りこぼし）で、実在しない出場を
作る方向の誤りは出ていない。

#### 表示側

- **出場歴の並びは新しい順、同じ年なら夏 → 春。**
  `season` は列挙型 `('spring','summer','autumn')` で Postgres は定義順で比較するため、
  `order("season", { ascending: false })` で夏が春の上に来る（`queries/schools.ts`）
- **勝敗は勝利数だけを出す。** 敗戦数はDBには入っているが表示しない
- **学校ページのバッジに春・夏それぞれの最高成績を出す**（`lib/koshien.ts` の
  `bestResultBySeason`）。成績が不明な出場しかない季はバッジを出さない。
  **「出場したが成績不明」を「初戦敗退」と混同しないため。**

### 集計をDBのビューにしなかった理由

ビューを足すと**人がSQL Editorで適用する作業が増え、忘れるとページが落ちる。**
対象は出場歴2,987件・学校687校で、1回あたり4リクエスト・1.5秒。
ページの `revalidate` は1日（出場歴が増えるのは年2回）。これで足りている。

重くなったら 0007 でビューを足して `src/lib/queries/rankings.ts` の中身だけ
差し替える。戻り値の形を保てば画面側は変えなくてよい。

**PostgREST は1回に1,000行しか返さない**ので、出場歴はページングで取っている。
`.range()` を使うときは**並び順を一意に決めてから**にすること
（`school_id, year, season`）。並びが不定だとページの境目で行が重複したり抜けたりする。

### リポジトリ内の生成データ

| `src/lib/data/koshien-tournaments.ts` | `build-koshien-summary.mjs` | 大会199件の出場校数・試合数 |

**どちらも生成物。直接編集しない。**


`koshien.sql` は `on conflict do update` なので、何度流しても安全。
流したあとに `select public.recalc_school_koshien_counts();` を忘れないこと。

- 21世紀枠は年に1〜3件しか増えないので、テーブルを1つ増やして適用の手間を

- 大会ごとの出場校数は「公立が何割か」の**分母**に使う。私立を含む数なので
  DBには無い（このサイトは公立しか収録しない）

### 21世紀枠の取り込み

出典は Wikipedia「選抜高等学校野球大会」の「21世紀枠出場校一覧」。
**大会別記事ではなく親記事を使っている**。独立した「21世紀枠」節を持つのは
26大会中11大会だけで、残りは選出校の表に紛れているため。親記事の一覧は
2001年から現在まで1つの表にまとまっていて書式も一貫している。

取り込むのは**年・地区区分・校名だけ**。

- **選考理由の文章は取り込まない。** 記事の文章を持ってくるとCC BY-SAの
  継承条件が発動する（事実データの抽出では発動しない）
- **成績もこの表からは取らない。** この表は「2回戦敗退」、DBは「ベスト16」と
  表記が違う。同じ出場が2つの表記を持つのを避け、DB側に一本化している

**統廃合前の校名は同じ年の出場校表から引き当てている。** 親記事の表は
「北海道女満別高等学校」のまま残っているが、大会別記事のほうは現存校
（北海道大空高等学校）に張り替えられている。21世紀枠の学校は必ずその年の
選抜に出場しているので、**同じ出典の中で現存校の記事名が手に入る**。
校名を推測で書き換えてはいない。

照合結果は70件中69件。残る1件は土佐（高知）で、これは私立なので
学校マスタに無くて正しい（Wikipedia自身も21世紀枠で選ばれた私立は
この1校だけと書いている）。

自己検証を2つ入れてある。どちらも現在0件。

| 検証 | 内容 |
|---|---|
| 1 | 照合できた学校が、その年の選抜の出場校の中にいるか（中止年を除く） |
| 2 | 表に書かれた都道府県と、照合先の学校の正式名称が食い違わないか |

### 表示で気をつけていること

- **「私立を収録していない」と各ページに必ず書く**（`DataNote` コンポーネント）。
  学校マスタが公立だけなので、ここでの1位は全国1位ではない
- **成績が不明な出場を「初戦敗退」に混ぜない。** 最高成績の一覧では、
  段階が確定しない学校はどの段階にも入れず、注記で数だけ出す
- **春・夏の切り替えはリンクで作る**（クライアントJSを使わない）。
  状態がURLに残るので共有でき、検索エンジンにも拾われる
- **地図の色はネイビーの濃淡だけ。** 明度だけで並べれば、色覚特性があっても
  白黒印刷でも段階の順序が保たれる。折れ線は色と線種の両方で見分ける
- **値の種類が段階数以下のときは分位で切らない。** 21世紀枠の選出回数のように
  1〜4しか値が無いデータを分位で切ると「1〜／1〜／1〜」という凡例になる

## 公立旋風の勝ち上がり（2026-08-12 実装）

公立旋風の詳細ページ（`/phenomenon/[slug]`）に、甲子園での勝ち上がりを
1試合ずつ出す。1回戦から決勝まで、回戦・対戦相手・スコア・寸評を縦に並べる。

|---|---|

| `src/components/phenomenon/TournamentRun.tsx` | 表示 |

### なぜDBに入れないのか

試合単位のテーブルを足すと、人がSQL Editorで流す作業が1つ増え、
流し忘れると詳細ページが落ちる。記事は数十件の規模で、更新も編集作業の
一部なので、コードと一緒にデプロイされるほうが事故が少ない。
記録・ランキングでビューを作らなかったのと同じ判断。

**`src/lib/content/` は手で書く編集コンテンツ。`src/lib/data/` は
スクリプトの生成物（直接編集しない）。** 紛らわしいので置き場所を分けてある。

`phenomena.slug` と `TournamentRun.phenomenonSlug` が対応している。
片方を変えるならもう片方も変えること（勝ち上がりが出なくなるだけで
ページは落ちないので、気づきにくい）。

### 出典の集め方

大会記事のブラケットには**最終スコアしか無い**。イニングごとの得点は
別のところから取る必要がある。

1. **旋風そのものの独立記事を先に探す。** 「金農旋風」には全6試合の
   Linescoreと試合経過がある。「大社旋風」は記事が無く、「がばい旋風」は
   大会記事へのリダイレクト。
2. **試合単体の記事を探す。** 「宇治山田商業対佐賀北延長15回引き分け再試合」
   のように、有名な試合には個別記事があってLinescoreを2つ持っている。
3. **無ければ運営者のスコアブック。** 当時つけた一次記録があるならそれが最良。

`scripts/fetch-wikipedia-pages.mjs` で記事名を指定して wikitext を取れる。

```
node scripts/fetch-wikipedia-pages.mjs "金農旋風" "秋田県立金足農業高等学校"
```

#### ★新聞社のスコアページは使わない

**一球速報.com とバーチャル高校野球は使えない。** 外した理由は著作権ではなく
**利用規約**で、上の「出典の選定」に条項まで控えてある。特に
バーチャル高校野球は第8項(3)で**営利目的の利用を禁じており、
目視での転記も塞がる**。「人が読んで数字を渡せば規約に触れない」は
**この2媒体には通用しない**（2026-08-12 にこの誤りをやりかけた）。

他の新聞社も「無断転載禁止」「営利利用禁止」を置いていることが多く、
**媒体を変える方向では解けにくい**。規約の壁を構造的に抜けるのは次の3つ。

| 手段 | 可否 | 備考 |
|---|---|---|
| 運営者自身のスコアブック | ◎ | 一次記録。規約に縛られない。**いま13試合ぶんある** |
| 市販の記録集（書籍） | ◎ | 書籍に利用規約は無い。事実の転記は自由 |
| 日本高野連の公式ページ | △ | 規約なし・一次情報だが**当年分しか残らない** |

**戦評の文章はどの出典でも写さない。** 事実だけを取って自分の言葉で書く。

⚠️ **出典の表示は実際の出所と一致させること。** 手元に同じ記録があっても、
私が転記した経路が別なら、その経路が本当の出所。読者に対する出典表示の
信頼性は、規約の問題より優先する。

### 現存校を「廃校」と取り違えていた（2026-08-12 に解決済み）

**福山（広島・市立）の2026年夏の初出場が、出場歴からも結果速報からも
まるごと落ちていた。**

Wikipedia の記事名が `福山市立福山中・高等学校`。中高一貫校の言い換え規則
（`candidates()`）が `中学校・高等学校` しか見ておらず、**「中学校」を「中」と
略した形**を素通りしていた。照合できなかった結果、`resolve-defunct-schools.mjs`
が「統廃合で消えた校名」と判断し、`data/school-successor.json` に
誠之館・葦陽を後身校の候補として並べてしまっていた。福山は現存する市立高校
（学校マスタの slug: `fukuyama`）で、廃校ではない。

| 直したもの | 内容 |
|---|---|
| `scripts/match-koshien.mjs` | `candidates()` に `中・高等学校` → `高等学校` を追加 |
| `scripts/build-live-results.mjs` | 代表校表の正式名称を素で引いていた。同じ `candidates()` を通すようにした |
| `data/school-successor.json` | 誤って入っていた福山の行を削除 |
| `supabase/fix_fukuyama_2026.sql` | **適用済み**（2026-08-12。出場歴 2,970 → 2,971 件） |

この形の記事名は出場歴データ全体で**この1件だけ**（`grep '中・高等学校'` で確認）。

**教訓: `school-successor.json` に載る＝廃校とは限らない。**

### 次戦の出典は2つある（2026-08-13 追加）

**日別ページだけだと、決まっている次戦が出せない。** 2026-08-13 の時点で
日別ページは 8/5〜8/13 の9日ぶんしか無く、鳴門渦潮の2回戦（8/14 第2試合・
対 霞ケ浦）はどこにも出てこなかった。だが**3回戦までの組み合わせは
8月1日の抽選で決まっている**（準々決勝以降だけ、3回戦から勝ちチーム主将が
各試合直後にくじを引く）。その決まっているぶんが組み合わせ表にある。

| 出典 | 分かること | `provisional` |
|---|---|---|
| 日別ページ | 日付・第何試合・**開始時刻**・対戦相手 | `false` |
| 組み合わせ表 | 日付（換算）・第何試合・対戦相手。**時刻は無い** | `true` |

**日別ページ由来を必ず優先する。** 組み合わせ表の日付は「第N日」からの
換算なので、実際の日程が出ていればそちらが正しい。

#### 組み合わせ表の読み方

罫線をGIF画像で描いた古い作りの `<table class="tournamentTable">` が13個並ぶ。
意味のあるセルは `td.teamName`（`鳴門渦潮 (徳島)`）と `td.gameDay`
（`第5日 第3試合`）の2つだけ。

**1つの table が、そのままブラケットの部分木の中置表記になっている。**
セルの列番号（colspan を数えたもの）が回戦の深さで、大きいほど木の上。
だから「いちばん列番号の大きい試合で左右に割る」を再帰すれば木になる。

```
[東筑 G1 神村学園] G3 [聖隷 G1 佐野日大]     ← G3 が2回戦、G1 が1回戦
```

**チームが1つも無い table（8〜12番目）は読まない。** 準々決勝以降は
くじ引きなので、線がつながっていても対戦相手は決まっていない。
つまり**各 table の根が3回戦**で、回戦名は根からの深さで振れる。

**勝敗は組み合わせ表からは読まない。** 表にもスコアはあるが、
日別ページのほうが確実（都道府県が併記されていて照合できる）。
組み合わせ表からは**形だけ**を取り、勝者は日別ページで解決する。

#### 「第N日」を日付に直す

日別ページの見出しが `8月9日(日) ＜大会5日目＞` なので、そこから
「大会何日目 → 日付」の対応表を作る。未発表の日は1日ずつ進むと仮定して
外挿するが、**分かっている日がすべて1日ずつ並んでいるときだけ**
（雨天順延が起きるとここが崩れる。崩れたら日付を出さず `第N日` を出す）。

**休養日は考えなくてよい。** 休養日は「3回戦2日目・準々決勝・準決勝の
各翌日」で、組み合わせ表から補うのは3回戦までなので必ず連続の区間に入る。

#### 検算

組み合わせ表には回戦名が書かれておらず「根が3回戦」という前提で深さから
振っている。**実施済みの試合と回戦名を突き合わせ、1件でも食い違ったら
組み合わせ表由来の次戦を出さない。** 間違った回戦名を出すより空のほうがよい。

### 照合（推測で結び付けない）

代表校ページの「地区名＋略称」を学校マスタに当てる。
候補は「校名」「校名から高校を除いたもの」「商業→商・工業→工・農業→農」
「別名（`name_aliases`）」。**同じ地区で2件以上に当たったら結び付けない。**
岐阜商業のように県立と市立が同名の地区があるため、取り違えるくらいなら
照合できなかったものとして報告する。

⚠️ 略称の規則は `src/lib/school-name.ts` にも同じものがある。
**スクリプトは .mjs なので TS を import できず、規則が二重にある。**
片方だけ直すと照合が落ちる（表示は壊れず、報告に出るだけ）。

### 県のページへの出し方（2026-08-13 実装）

`/prefectures/<slug>` の「学校一覧」の下に、その県の試合を出している。

- ★**索引は動的 import にすること**（`REGIONAL_LOADERS`）。全県を静的 import すると
  **どの県のページにも全国ぶんが入る**（6県で約430KB、47県なら6MB）。
  `getRegionalDistrict()` がこの表を引く
- ★**索引も生成物。手で書かない。** アダプタを足して索引を直し忘れると、
  「データはあるのにページに出ない」という気づきにくい壊れ方をする。
  **まだ生成していない県は索引に載せない**（存在しないファイルの import でビルドが落ちる）
- ★**索引のファイル名を `index.ts` にしない**（`loaders.ts` にしてある）。
  ディレクトリ指定の import（`@/lib/data/regional`）は**本番ビルドは通るのに
  `next dev` のブラウザ側のコンパイルだけが「Module not found」**になり、
  リクエストのたびにエラーが出る（画面は出るので気づきにくい）
- **出すのはいちばん新しい季節だけ**（`latestSeasonGames`）。春夏秋を日付順に混ぜると、

- ★**日付に年を付ける**（`formatRegionalDateWithYear`）。トップは「7月26日」と
  年を省いているが、あちらは抜粋を120日以内に限ってあるから。県のページは

13. **古い年の節がページの下に残っていることがある**（山梨の春は2023年ぶんが残っていた）。

14. **回戦が出典に無い日がある。** 山梨は準々決勝から先にしか回戦の見出しを付けない
    （1〜3回戦の日は日付と球場だけ）。**推測で埋めない。** `round: null` のまま持ち、
    画面側で中黒が宙に浮かないようにする（`RegionalResultsCard`）
15. ★**`--pref` で1県だけ動かしたときは抜粋を書き換えない。** 抜粋は全国から選ぶので、
    1県ぶんで上書きすると**他の県がトップから消える**（実際にやった）。
    スクリプト側で止めてあるが、生成物を見るときは県ごとのファイルと
    抜粋の更新タイミングが違うことを頭に入れておく
16. ★**長音符（ー）をハイフンに寄せない**（2026-08-13 に修正）。スコアの区切りを
    そろえるつもりで `ー` まで `-` にしていたため、**「ルーテル学院」が「ル-テル学院」**、
    「リブワーク藤崎台球場」が「リブワ-ク…」になって画面に出ていた（4県で86か所）。
    球場名を拾う正規表現の「ドーム」も同じ理由で効いていなかった。
    **数字に挟まれているときだけ**区切りとして扱う
17. **見出しの記号を球場名に巻き込まない。** 熊本は `■リブワーク藤崎台球場` と書く
18. ★**表示用の空白は生成時に詰める**（「有 明」「岱 志」「横 浜」）。
    出典が表の見た目をそろえるために入れているもので、校名の一部ではない。
    **連合チームだけは詰めない**（「寒川 藤沢総合 深沢 厚木清南」が1校に見える）
19. ★**生成物を `index.ts` にしない。** `@/lib/data/regional` のようなディレクトリ指定の

### 取りこぼしの検算

★**準々決勝・準決勝・決勝の試合数が 4・2・1 になっているか**を見る。

- **校名では検算しない**（上の落とし穴5）
- **全回戦に半分を要求してはいけない。** シード校が2回戦・3回戦から登場するので
  半分にならない（神奈川は2回戦66→3回戦32、埼玉は2回戦74→3回戦32）。

- ★**準々決勝は「多い」を異常としない**（2026-08-13 に緩めた）。
  山梨の秋季県大会は**準々決勝が6試合ある**（敗者にもう一度機会がある形式で、

  （実際に、別の大会が混ざっているのをこれで見つけた）

## SEO（2026-08-12 に大きな修正が2つ）

### 1. sitemap から2,505校が抜けていた（修正済み）

`getAllSchoolSlugs()` がページングしておらず、**PostgREST の1,000行制限で
3,505校のうち1,000校しか返っていなかった。** sitemap も
`generateStaticParams` もこれを使っているので、公開していたら
2,505校が sitemap から丸ごと抜けたまま気づかなかった可能性が高い。

**このリポジトリで3度目の同じ罠。**（出場歴の集計・ランキング・今回）
`select()` で全件取るコードを書いたら、**必ず一意な並び順を決めてページングする。**

### 2. 約2,827校が「薄いコンテンツ」だった（noindex にした）

甲子園出場歴があるのは**679校だけ**。残り約2,827校のページは校名・所在地・
区分しか無く、あとは「まだありません」が3つ並ぶだけになる。
同じ形の空ページが2,800枚あると、サイト全体が薄いと判定され、
**ランキングや公立旋風など中身のあるページの評価まで巻き添えになる。**

対処は次の2点。中身が入れば**自動で両方に復帰する**ので手作業は要らない。

| 場所 | やっていること |
|---|---|
| `app/schools/[slug]/page.tsx` の `isIndexable()` | 出場歴が無ければ `noindex, follow` |
| `getIndexableSchoolSlugs()` | sitemap には出場歴のある学校だけ載せる |

**`follow` は残している。** 閲覧も内部リンクの評価も従来どおり。

⚠️ **戦績（`school_records`）やニュースを入れ始めたら `isIndexable()` に
それも足すこと。** いまは実データが0件なので出場歴だけで判定している。

### SEOで狙うべきところ

**結果速報で検索流入は取れない。** 「◯◯高校 結果」で朝日・毎日・スポーツ紙に
速度でも権威でも勝てない。結果速報の価値は回遊と再訪であって検索ではない。

検索で取れるのはストック側。

| 狙える | 例 |
|---|---|
| 学校の記録 | 「熊本工業 甲子園 出場回数」 |
| ランキング | 「公立 甲子園 優勝」「21世紀枠 一覧」 |
| 公立旋風 | 「金農旋風」「大社 2024」 |
| 都道府県 | 「島根 公立高校 野球」 |

### 守りの構造

**anonキーは公開鍵なので、アプリを経由しない書き込みが常に可能。**
Next.js の API ルートを挟んでも裏口は塞げないため、検査はすべてDB側にある。

| 層 | 何をしているか |
|---|---|
| RLSポリシー | 投稿できる行の形を縛る（`status = 'draft'` のみ等） |
| トリガ | `status`・公開日時をサーバ側で強制上書き。ポリシーは列追加時の追従漏れがあるため二重化 |
| CHECK制約 | 本文200字・表示名20字・`visitor_key` の形（16〜64字の英数字とハイフン） |
| レート制限 | 同一 `visitor_key` から1時間5件まで |
| 権限 | anon から `update` / `delete` を revoke |

`school_cheers` と `poll_votes` は **書けるが読めない**（select ポリシーを作っていない）。
誰がどこを応援したかを返す必要が無く、返せば利用者の行動履歴を配ることになるため。
表示に使う数は `schools.cheer_count` と `poll_options.vote_count` にある。

**visitor_key は本人確認ではない。** ブラウザの localStorage に置くUUIDで、
消せば別人になれる。二重クリックとカジュアルな連投を防ぐためのもの。
本格的な荒らし対策が要るようになったら Supabase Auth を入れ、`user.id` に置き換える。

### 運用でやること

- **投稿の承認。** `cheer_messages` は必ず `draft` で入る。ダッシュボードの
  Table Editor で `status` を `published` にすると公開される（`published_at` は自動）
- **管理画面はまだ無い。** 件数が増えたら作る
- **公開前に必要なもの** — 利用者の投稿を預かる以上、運営者情報の設定・
  利用規約・削除方針・通報導線は公開までに揃える（下記「公開前に必ずやること」）

```
node --env-file=.env.local scripts/check-community.mjs
```

RLSとトリガが効いているかを anon キーで13項目確認する。**本番DBに書き込む**ので、
実行後は出力される掃除用SQLでテスト行を消すこと。

### MVPに含めていないもの

ユーザー登録・ログイン・学校フォロー・投稿・コメント・通知 /
ニュース自動収集 / 管理画面 / X自動投稿 / 広告の実配信 / アフィリエイト

いずれも将来追加しやすい形にはしてある（`AdSlot` の空実装、RLSの先行有効化など）。

## 都道府県タイル地図（2026-08-12 作り直し）

日本の形を模した12列×14行の配置をやめ、**甲子園の出場校一覧でおなじみの
10列×10行**に変えた。北海道・東北を右上にまとめ、残り40地区を10列×4行に
敷き詰める並び。マス目の隙間が減り、1マスを約100pxまで大きく取れる。

| ファイル | 何が入っているか |
|---|---|
| `src/lib/constants.ts` | `mapCol` / `mapRow` / `mapSpan`（北海道の2地区だけ横2マス）、`MAP_COLUMNS` `MAP_ROWS` |
| `src/app/globals.css` | `.prefecture-map*`。素のマス目は34rem〜、校名入りは46rem〜 |
| `src/components/schools/PrefectureMap.tsx` | 都道府県セレクタ |
| `src/components/schools/PrefectureMapGuide.tsx` | トップで左上の空きに入れる案内 |
| `src/components/rankings/PrefectureHeatMap.tsx` | 同じCSSに乗る色分け地図 |

**配列 `PREFECTURES` の並びはJISコード順のまま。** 狭い画面では地方別の
一覧に切り替わり、そのときこの並びがそのまま読み上げ順になるため。

### 左上の空きを使う（`heading` / `aside`。2026-08-13 追加）

10列×10行に並べると、北海道と東北だけが9〜10列目に縦に並ぶので
**1〜8列目・1〜5行目が丸ごと空く**。トップではここが大きな余白になっていた。

`PrefectureMap` の `heading` と `aside` に渡したものがこの空きに入る。
トップでは**セクションの見出し＋凡例・数字・「学校名から探す」**を入れてある。
以前は見出しが地図の上、残りが地図の下にあり、地図の左上が空いたままだった。

| 欄 | 置き場所 | 中身 |
|---|---|---|
| `.prefecture-map__heading` | 1〜2行目（`align-self: start`） | `<h2>公立高校を探す</h2>` と説明文 |
| `.prefecture-map__aside` | 3〜5行目。**入り切らなければ地図の下**（11行目） | 凡例・数字・「学校名から探す」 |

- **見出しは必ず左上に置く。** 地図の外（上）に出すと、地図の左上が見出しの
  ぶんだけ下から始まって右隣の北北海道と上端が揃わず、そこに空きができる。
  左上に入れると上端が完全に揃う（実測でずれ0px）
- **狭いときは地図が横並びのボタンに変わる**ので、`order` で見出しを先頭・
  案内を最後に回す。マークアップはどちらの形でも1つのまま。
  **見出しを後ろに回さないこと**（h2が地区ボタンの下に来る）
- ★**中身の高さを割り当てた行ぶんに収めること。** グリッドの行は `auto` なので、
  ここが高いと**同じ行にある北海道・東北のマスまで一緒に伸びて**、
  他の行とマスの高さが揃わなくなる（校名入りのマスは `height: 100%` で行に追従する）
- **案内が左上に入るのはコンテナ54rem以上のときだけ。** それ未満では地図の下に回す。
  3〜5行目は215〜270pxしかなく、案内が「凡例｜数字と導線」の2列（約188px）に
  なっていないと入らないため。**54remは内側の余白まで数えて出した値** —
  2列になるのは中身40rem＝640pxからで、枠の `p-4`（左右16px）を足して672px、
  枠は10列中8列ぶん＝約0.8倍なので 672÷0.8≒840px、余裕をみて864px。
  51remで切ったときは枠652px→中身620pxで1列のまま入り、マスを押した
- 足したあとは**入れる前と行の高さが変わっていないことを実測する。**
  `aside.style.display = 'none'` を挟んで各 `li` の高さを比べるのが早い。
  1200〜420pxの17点で一致を確認済み（2026-08-13）
- 数字は**地図から読み取れるものだけ**にしてある。地図と食い違う数字を
  並べると、どちらが正なのか分からなくなるため

### マスの中に出している校名

`PrefectureMap` に `latest` を渡すと、マスの中に**春・夏それぞれで
その地区から最後に甲子園へ出た公立校**が出る（トップと `/prefectures`）。

- データは `latestPublicByPrefecture()`（`src/lib/queries/rankings.ts`）。
  `getKoshienDataset()` の集計結果から引くので**DBへの追加リクエストは無い**
- **私立は学校マスタに無いので「その年の代表校」ではない。**
  2026年夏の兵庫は「社」で代表校と一致するが、愛知は代表校の享栄（私立）ではなく
  2008年の大府が出る。画面には必ず年を添え、公立限定である旨を書くこと
- 校名は `shortSchoolName()`（`src/lib/school-name.ts`）で短くする。下記参照
- `highlightYear` の春夏そろって出場している地区だけオレンジで囲う。
  **色だけで意味を持たせず、凡例を文字で必ず出す**
- 「今年」は今日の日付ではなく `dataset.latestYear`。1〜3月は今年の大会が
  まだ無く、日付で判定するとどこにも色が付かないため
- 校名は2行で打ち切る。3行に折れると同じ行のマスと高さが合わなくなる

`/schools` の地図だけは校名を出していない。あれは検索結果の絞り込み
コントロールで、大きいマスにすると結果一覧が画面外へ押し出されるため。

## 一覧で使う短い校名（`src/lib/school-name.ts`）

学校マスタの `name` は「佐賀商業高校」のように必ず種別まで入っている。
一覧・タイル・ランキングでは末尾の**「高校」だけ**を落とす。

使っている場所: 公立旋風（トップ）・注目の公立高校・都道府県タイル地図。
**学校ページの見出しと検索結果では使わない。** そこはどの学校かを一意に
伝える必要があるため、マスタの名前をそのまま出す。

### 落としてはいけないもの

| 名前 | 落とすと | だから |
|---|---|---|
| 広島中等教育学校 | 広島 | 何の学校か分からない |
| 米子工業高専 | 米子工業 | 高校の米子工業と区別が付かない |
| 三刀屋高校掛合分校 | — | 分校名まで含めてひとつの名前。末尾が「分校」なので自然に対象外 |

### 短くすると衝突する学校（slugで上書き）

| slug | 出す名前 | 理由 |
|---|---|---|
| `gifushogyo` | 県立岐阜商業 | 学校マスタではどちらも「岐阜商業高校」。落とすと同じ名前になる |
| `gifu-gifushogyo` | 市立岐阜商業 | 同上（岐阜市立） |
| `wakayama-wakayama` | 市立和歌山 | 「和歌山」だけだと地区名と紛れる |

いずれも高校野球で実際に使われている呼び方。**増やすときは「短くした結果
ぶつかるから」を理由にすること。** 好みで別名を付け始めると、検索して来た人が
同じ学校だと気付けなくなる。

なお学校マスタには**表示名が重複している学校が他にも多数ある**
（「三島高校」「向陽高校」など、別の県に同名校がある）。県が違えば
一覧では都道府県名が並ぶので取り違えは起きない。上の3件は
**同じ県の中で**ぶつかる／地区名と紛れるので上書きしている。

## 学校ごとのビジュアル（2026-08-12 実装）

`src/components/schools/SchoolEmblem.tsx`。**ユニフォームの胸文字を模した記章**を
その場で描く。写真も画像ファイルも使わないので、全3,531校に即座に付く。

写真（`image_url`）がある学校ではそちらが優先される。`Thumbnail` に
`school={{ name, slug }}` を渡した場所だけで働く。

使っている場所: 公立旋風（トップ・`/phenomenon` 一覧）・注目の公立高校・
学校詳細ページのヘッダー。

大きさで描き分ける（`variant`）。同じ比率で拡大すると詳細ページで文字が
90pxを超えて画面を占領してしまうため。

| variant | 使う場所 | 文字の最大 |
|---|---|---|
| `chip`（既定） | 一覧のサムネイル（64〜112px） | 34（viewBox座標） |
| `panel` | 学校詳細ページの写真枠（256px前後） | 22 |

### なぜ校章やユニフォーム写真ではないのか

| | 使えない理由 |
|---|---|
| 校章 | 学校（またはデザイナー）の著作物。多くは商標登録もされている |
| ユニフォーム・キャップの実物写真 | 撮影者の著作権 |

いずれも**装飾として載せる用途では引用も報道も成立しない。** 679校ぶんの
個別許諾は現実的ではないので、権利の要らない材料（校名の文字と、slugから
決まる色）だけで描いている。

### 決めたこと

- **色は実際のチームカラーではない。** 機械的に当てられないし、当て推量で
  置くと誤情報になる。slugから決まるサイトの配色（5色）で、白文字が
  4.5:1を満たす濃さのものだけ。**色数を増やすほど「本物の色だ」と
  誤解されやすくなる**ので、見分けが付く最小限に絞ってある
- **キャップの形を描くのはやめた。** 実寸（公立旋風のサムネイルは64×48px）だと
  帽子と分かる形にならず、そのぶん文字が小さくなって読めなかった。
  この大きさで学校を見分けさせるのは絵ではなく文字
- 文字数は `capLabel()` で縮める（商業→商・工業→工・農業→農）。
  甲子園出場校679校のうち**94%が4文字以内**に収まる（実測）。5文字以上は2行
- 和文は1文字＝1emなので、**文字数×フォントサイズ＝幅**。これで幅から逆算して
  フォントサイズを決めており、`textLength` で詰めて字を歪めていない

### 学校詳細ページのヘッダー（2026-08-12 に組み替え）

**横帯（約5:1）をやめ、写真を左・情報を右の2列にした。**

手に入る学校の写真は ja.wikipedia の校舎写真で、**縦横比は中央値1.33（4:3）、
上位10%でも1.50**（実測）。5:1の帯に嵌めると高さの7割以上が捨てられ、
建物の横帯しか残らない。

実装で引っかかった点を2つ残しておく。

- **`sm:items-start` が要る。** flexの既定（stretch）だと写真が右の列の高さに
  引き伸ばされ、`aspect-[4/3]` が効かずに縦長へ切り取られる（実測で0.94になった）
- **カードの端いっぱいに広げず、余白の内側に置いている。** 端まで広げて高さを
  右の列に合わせると、右の情報量（キャッチコピーの有無、バッジの数）で
  写真の縦横比が学校ごとに変わり、切り取られる量がばらつく

狭い画面では写真を上に積む。どちらの幅でも4:3のまま、切らずに出る。

### Wikipediaの校舎写真（2026-08-12 実装）

`scripts/build-school-images.mjs`。ja.wikipedia の各学校記事から代表画像を取り、
`public/schools/<slug>.webp`（640×480）に落として、`schools.image_*` を
更新するSQL（`supabase/school_images.sql`）を作る。

```
node scripts/build-school-images.mjs --koshien --limit 20   # 試す
node scripts/build-school-images.mjs --koshien              # 甲子園出場校
node scripts/build-school-images.mjs --all                  # 全3,531校
```

**中断しても安全。** メタデータは `data/school-images.json` に、画像は
`public/schools/` に残るので、流し直すと足りないぶんだけ取りに行く。

#### なぜ Supabase Storage ではなく public/ なのか

設計判断⑫の目的は「外部URLを直接参照しない」ことで、Storage自体が目的ではない。
`public/` でも同じ目的を満たしたうえで、**バケットの作成も service_role キーも
要らない**（このリポジトリは service_role キーを持たない運用）。
ロゴとヒーロー写真も既に `public/` にある。next/image はローカルのパスを
`remotePatterns` 無しで扱える。

⚠️ **`public/schools/` は必ずコミットすること。** gitに入れないと
Vercelのビルドに画像が含まれず、全部リンク切れになる。

#### 踏んだ落とし穴（4つとも実際に踏んだ）

| | 症状 | 原因 |
|---|---|---|
| User-Agent に日本語 | `fetch` が例外 | HTTPヘッダーはASCIIのみ |
| ファイルが1件も一致しない | 画像0枚のまま静かに終わる | `File:` で問い合わせても応答は `ファイル:` に正規化される |
| アンダースコア付きだけ落ちる | 17件中5件しか取れない | MediaWiki がタイトルの `_` を空白に正規化する |
| 640枚中526枚が失敗 | HTTP 429 | 150ms間隔は速すぎる。400ms＋`Retry-After` 準拠の再試行にした |

#### 校舎写真ではない画像を落とす

`pageimages` が返すのは記事の代表画像で、**校舎写真とは限らない。**
実際に出雲商業と松江北の代表画像はどちらも `Location map Shimane.svg`
（県の位置図）だった。そのまま貼るとピンク色の県地図が並ぶ。

2段構えで落としている。

1. **名前と拡張子** … SVG、`location map` / 地図 / 位置図 / 校章 / logo など
2. **複数校が同じ画像を使っていたら除外** … 校舎写真が別の学校と共有される
   ことはない。1をすり抜けた汎用画像もここで落ちる

除外された学校は記章（`SchoolEmblem`）にフォールバックする。

#### 取り込み結果（2026-08-12・甲子園出場校679校）

| | 件数 |
|---|---|
| 写真あり | **622校** |
| 記事に画像が無い | 54校 |
| 校舎写真ではない画像しか無い（位置図など） | 2校 |
| ライセンスが判別できず除外 | 2校（numazu・maebashi） |
| GFDL単独のため除外 | 1校（kagoshimagyokuryu） |

容量は **32.9MB**（1枚あたり平均54KB / 640×480 webp）。
無作為に抜き取った40枚を目視し、地図・校章の混入が無いことを確認済み。

ライセンスの内訳は CC BY-SA 3.0 が242、CC BY-SA 4.0 が188、
パブリックドメイン104、CC BY 3.0 が33、CC0 が32、その他23。

**全3,531校に広げるかは保留。** カバー率は約92%（実測）なので写真は
3,250枚・約160MBになる。`--all` を付けると差分だけ取得する。

#### 使わないライセンス

- **判別できないもの** … Commonsのファイルページに機械可読なライセンス情報が
  無いものが2件あった。ja.wikipedia に載っている以上フリーの可能性は高いが、
  **可能性で他人の著作物を使わない**
- **GFDL単独** … 複製にライセンス全文を添えることを求める。写真1枚のために
  全文を載せる運用は現実的でなく、リンクで済ませると条件を満たさない

どちらも記章（`SchoolEmblem`）にフォールバックする。CC系・パブリックドメイン・
FAL・Attribution・Copyrighted free use は、撮影者＋ライセンス名＋出典リンク＋
改変の告知で足りる。

#### 帰属表示

**CC BY 系は帰属表示が法的義務。** `image_credit` に
`撮影者 / ライセンス名（縮小・切り抜き）` を入れ、学校詳細ページでは
`image_source_url`（Commonsのファイルページ）へのリンクとして出している。

**写真に重ねず、下にキャプションとして置いている。** CC BY-SA は
元の作品へのリンクも求めるが、10pxの帯を256px幅の写真に重ねると
入りきらずリンクも押しにくい。縮小・切り抜きは改変にあたるので、
その旨も文言に含めてある。

## 設計上の決めごと

`AGENTS.md` に集約してある。**コードを触る前に必ず読むこと。**
特に重要なのは以下。

- 収録対象は「私立以外」。**国立・高専も含む**
- 東京都立**国立**高校（くにたち）は「都立」。設置区分を機械判定しない
- ニュースは全文転載しない。見出し＋自作要約＋出典リンクまで
- 選手個人のページ・個人成績は作らない
- 未公開コンテンツの除外は**RLSで強制**。クエリに `status='published'` を書かない
- `src/types/database.ts` は手書き。マイグレーションを変えたら必ず合わせる
- オレンジは白地では4.5:1を取れない。白地の文字には `accent-800` を使う
